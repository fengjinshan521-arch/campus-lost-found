# 匹配推荐算法与状态机建模

## 1. 匹配推荐：六因子加权算法

### 1.1 总体公式

```
score = Σ(wᵢ × fᵢ) / Σ(wᵢ)        fᵢ ∈ [0, 1]，wᵢ 为权重
```

| 因子 | 权重 | 计算方式 | 取值 |
|---|---|---|---|
| category 类别 | 0.25 | 同分类 1.0；同父级二级分类 0.6；否则 0 | 0 / 0.6 / 1 |
| keyword 关键词 | 0.20 | 标题 + 关键词分词集合的 Jaccard 相似度 | 0~1 |
| location 地点 | 0.15 | 同分区 1.0；邻接分区 0.5；否则 0.1；地点原文互相包含 +0.1 | 0.1~1 |
| time 时间 | 0.15 | `exp(-Δdays / 7)` 指数衰减；拾获早于遗失超过 1 天判 0.1 | 0~1 |
| feature 特征 | 0.15 | 特征标签集合 Jaccard | 0~1 |
| text 文本 | 0.10 | 描述文本的词频余弦相似度 | 0~1 |

### 1.2 分词方案

不引入 jieba 等外部分词库（避免部署依赖问题）：

- 英文与数字按正则词切分（`iPhone13` → `iphone13`）
- 中文按 2-gram 切分（"黑色手机" → `黑色`、`色手`、`手机`）
- 去除停用词（的、了、在、是 …）

### 1.3 三个关键设计

1. **可解释**：每个因子的得分与权重写入 `t_match_record.detail`（JSON），前端渲染成"推荐理由"条形图，答辩可直接展示为什么推荐它。
   ```json
   {"factors": {"category": 1.0, "keyword": 0.62, "location": 1.0, "time": 0.87, "feature": 1.0, "text": 0.55},
    "weights": {"category": 0.25, "keyword": 0.20, "location": 0.15, "time": 0.15, "feature": 0.15, "text": 0.10},
    "total": 0.83}
   ```
2. **阈值过滤**：低于 `MATCH_THRESHOLD`（默认 0.45）不写入推荐、不推送通知，避免噪声打扰。
3. **幂等**：`(found_item_id, lost_item_id)` 联合唯一约束，重复计算只更新分数，不会产生重复记录。

### 1.4 参数可调

权重来源优先级：`t_system_setting.key='match_weights'` > `.env` / `app/config.py` 默认值。
后台可在数据库直接改 JSON 调参，无需重启即可生效（论文第 4 章可做对比实验）。

## 2. 状态机建模

### 2.1 物品状态流转（邻接表）

```python
ITEM_TRANSITIONS = {
    "unclaimed": {"pending", "cancelled"},          # 未认领 → 待确认 / 已撤销
    "pending":   {"unclaimed", "claimed", "cancelled"},  # 待确认 → 回退 / 已认领 / 已撤销
    "claimed":   {"archived"},                      # 已认领 → 已归档
    "archived":  set(),                             # 终态
    "cancelled": set(),                             # 终态
}
```

图示：

```
未认领 ──提交认领──▶ 待确认 ──审核通过──▶ 已认领 ──归档──▶ 已归档（终态）
   │                   │
   │                   └──驳回（无其它待审申请）──▶ 回退未认领
   └──撤销──▶ 已撤销（终态）
```

### 2.2 认领单状态流转

```python
CLAIM_TRANSITIONS = {
    "pending":  {"approved", "rejected", "cancelled"},
    "approved": {"archived"},
    "rejected": set(),
    "cancelled": set(),
    "archived": set(),
}
```

### 2.3 强制约束

- 所有状态变更必须经过同一入口 `assert_item_transition()` / `assert_claim_transition()`，非法流转抛 `InvalidTransition`，由全局异常处理器转成 HTTP 400（code=10）。
- 审核通过时联动三件事：物品置为已认领、同物品其它待审申请自动驳回、关联寻物启事同步置为已认领。
- 驳回时若无其它待审申请，物品回退到未认领，并扣减申请人信用分 2 分。
- 业务规则：不能认领自己登记的物品；同一人对同一物品不可重复提交待审申请；认领超时 72 小时自动提醒（可挂定时任务）。

## 3. 算法验证用例（tests/test_match.py）

| 用例 | 断言 |
|---|---|
| 同类别同分区 | 综合得分 ≥ 0.7 |
| 跨类别 | `factors.category == 0` 且综合分 < 0.45 |
| 时间衰减 | 相隔 1 天的时间因子 > 相隔 30 天 |
| 地点邻接 | 邻接分区得分 > 远端分区 |
| 阈值过滤 | 低相似组合不进入推荐列表 |
| 幂等 | 重复计算 3 次仅产生 1 条匹配记录 |
