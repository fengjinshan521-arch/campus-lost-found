# 数据库设计说明

- 数据库：MySQL 8.0，库名 `campus_lostfound`
- 字符集：`utf8mb4` / 排序规则 `utf8mb4_unicode_ci`（支持 emoji 与生僻字）
- 建表脚本：`server/sql/schema.sql`（结构与 ORM 模型完全一致，可由 `mysqldump` 复核）
- 初始化数据：`server/sql/init_data.sql`（分类、管理员、系统参数）
- 一键建库：`python scripts/init_db.py [--drop]`

## 1. 表清单（11 张）

| 表名 | 说明 | 主要字段 | 外键 |
|---|---|---|---|
| `t_user` | 用户 | username(唯一)、student_no、real_name、**password_hash + salt**、role、status、credit_score、verified | — |
| `t_login_attempt` | 登录失败记录 | username、ip、success、locked_until | — |
| `t_category` | 物品分类 | name、code、parent_id（自引用）、sort_order、is_active | parent_id → t_category.id |
| `t_found_item` | 拾获登记 | code(LF-)、title、description、features(JSON)、keywords、found_place、found_zone、found_time、storage_place、images(JSON)、is_sensitive、status、claimed_by | founder_id → t_user；category_id → t_category；claimed_by → t_user |
| `t_lost_item` | 寻物启事 | code(XS-)、title、lost_place、lost_zone、lost_time、reward、is_urgent、status、matched_found_id | owner_id → t_user；category_id → t_category；matched_found_id → t_found_item |
| `t_claim` | 认领记录 | claim_no(RQ-)、claim_type、status、reason、evidence(JSON)、contact、handler_id、handled_at、archived_at | found_item_id → t_found_item；lost_item_id → t_lost_item；claimant_id → t_user；handler_id → t_user |
| `t_match_record` | 匹配记录 | score、detail(JSON 因子明细)、level、status | found_item_id → t_found_item；lost_item_id → t_lost_item；**联合唯一约束 uq_match_pair** |
| `t_notification` | 站内通知 | type、title、content、related_type/id、link、is_read、read_at | user_id → t_user |
| `t_operation_log` | 操作日志 | action、target_type、target_id、detail(JSON)、ip、user_agent、result、username（冗余） | user_id → t_user（ON DELETE SET NULL） |
| `t_attachment` | 附件 | entity_type、entity_id、original_name、saved_name、rel_path、size、**checksum(sha256)** | uploader_id → t_user |
| `t_system_setting` | 系统参数 | key、value、remark | — |

## 2. 索引设计

```sql
-- 物品：状态 + 时间（列表页默认排序）、分类 + 状态（筛选）
idx_found_status_time  (status, found_time)
idx_found_cat_status   (category_id, status)
idx_lost_status_time   (status, lost_time)
idx_lost_cat_status    (category_id, status)

-- 认领单：按物品查待审、按状态筛选
idx_claim_item         (found_item_id, status)
idx_claim_status       (status)

-- 通知：用户未读计数
idx_notify_user_read   (user_id, is_read)

-- 日志：按业务对象追溯
idx_log_target         (target_type, target_id)

-- 匹配：按分数排序；唯一约束保证幂等
idx_match_score        (score)
uq_match_pair          (found_item_id, lost_item_id)  -- UNIQUE
```

## 3. 主外键关系图（文字版）

```
t_user ──┬─< t_found_item (founder_id / claimed_by)
         ├─< t_lost_item  (owner_id)
         ├─< t_claim      (claimant_id / handler_id)
         ├─< t_notification
         ├─< t_operation_log   (用户注销后 user_id 置空，username 冗余保留)
         └─< t_attachment

t_category ──< t_category (parent_id 自引用，支持二级分类)
          ──< t_found_item / t_lost_item

t_found_item ──< t_claim  (found_item_id)
             ──< t_match_record (found_item_id)
t_lost_item  ──< t_match_record (lost_item_id)
             ──< t_claim        (lost_item_id, 可空)
t_claim      ── 无子表，通过 t_operation_log(target_type='claim') 追溯
```

## 4. 状态字段取值

**物品状态 `status`**：`unclaimed` 未认领 / `pending` 待确认 / `claimed` 已认领 / `archived` 已归档 / `cancelled` 已撤销

**认领单状态 `status`**：`pending` 待确认 / `approved` 已认领 / `rejected` 已驳回 / `cancelled` 已取消 / `archived` 已归档

**匹配等级 `level`**：`high`(≥0.75) / `medium`(≥0.45) / `low`

## 5. 安全与合规设计

- 密码：`password_hash` 与 `salt` 分离存储，PBKDF2-HMAC-SHA256，12 万次迭代，每用户独立随机盐。
- 脱敏：手机号、邮箱、学号在列表与详情接口按"是否本人/职工"动态脱敏；证件类物品（`is_sensitive=1`）对无关用户隐藏描述与图片。
- 附件：保存原始名、随机存储名、字节大小与 sha256，防止文件被静默替换。
- 日志：用户注销后 `user_id` 置空但 `username` 保留，保证历史责任可追溯。
