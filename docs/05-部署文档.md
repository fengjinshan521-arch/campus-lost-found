# 部署文档（校园网环境）

## 1. 部署架构

```
浏览器 ──HTTP 80──▶ Nginx ──静态 /assets /uploads 直接返回
                       └──/api ──▶ waitress(5000) ──▶ Flask 应用 ──▶ MySQL 8.0
```

- 前端：`npm run build` 产出 `web/dist`，由 Nginx 直接托管（或拷贝到后端静态目录做同源部署）
- 后端：Windows Server 用 `waitress-serve`，Linux 用 `gunicorn` + systemd
- 数据库：MySQL 8.0，专用账号 + IP 限制 + 每日备份

## 2. 环境准备

```bash
# 后端
cd E:/campus-lost-found/server
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
copy .env.example .env        # 然后修改 SECRET_KEY 与 DATABASE_URL

# 前端
cd ../web
npm install
npm run build
```

## 3. 数据库（MySQL 8.0）

```sql
-- 1) 建库
CREATE DATABASE campus_lostfound
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 2) 建专用账号并限制来源（生产环境不要用 root）
CREATE USER 'lostfound'@'10.%' IDENTIFIED BY 'StrongPassword!2026';
GRANT SELECT, INSERT, UPDATE, DELETE ON campus_lostfound.* TO 'lostfound'@'10.%';
FLUSH PRIVILEGES;

-- 3) 建表与初始化
--    方式A：python scripts/init_db.py
--    方式B：mysql -u root -p campus_lostfound < sql/schema.sql
--           mysql -u root -p campus_lostfound < sql/init_data.sql
```

> 密码含 `@` `#` `!` 等特殊字符时，在连接串里必须做 URL 编码：`@`→`%40`、`#`→`%23`、`!`→`%21`。

## 4. 启动后端

### 4.1 Windows Server（waitress）

```bat
cd E:\campus-lost-found\server
set FLASK_ENV=production
waitress-serve --host 0.0.0.0 --port 5000 --threads 8 run:app
```

或用提供的脚本：`deploy\start_waitress.bat`。
生产环境建议用「任务计划程序」或 NSSM 将其注册为服务，保证开机自启。

### 4.2 Linux（gunicorn + systemd）

```bash
gunicorn -w 4 -b 127.0.0.1:5000 "run:app"
sudo cp deploy/lostfound.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now lostfound
```

## 5. Nginx 配置（见 `deploy/nginx-lostfound.conf`）

```nginx
server {
    listen 80;
    server_name lostfound.campus.edu.cn;

    root /var/www/campus-lost-found/web/dist;
    index index.html;

    # 前端静态资源
    location / { try_files $uri $uri/ /index.html; }

    # 反向代理 API
    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 上传图片（也可由后端提供）
    location /uploads/ { proxy_pass http://127.0.0.1:5000; }

    client_max_body_size 5m;
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}
```

若前后端同源部署且 Nginx 直接托管 `server/instance/uploads`，把 `/uploads/` 改为：

```nginx
location /uploads/ { alias /var/www/campus-lost-found/server/instance/uploads/; }
```

## 6. 校园网访问策略

| 场景 | 做法 |
|---|---|
| 仅校内可访问 | 服务绑定内网 IP，防火墙仅放行校园网段（如 `10.0.0.0/8`）；Nginx 加 `allow 10.0.0.0/8; deny all;` |
| 需校外访问 | 走学校 VPN 或统一身份认证（CAS）反向代理；本项目已预留 `/auth/verify` 接口，替换内部实现即可对接 |
| HTTPS | 申请学校证书或使用内网 CA，`SESSION_COOKIE_SECURE=True`（ProductionConfig 已开启） |

## 7. 备份与监控

```bash
# 每日 02:00 备份数据库（Windows 可用任务计划程序调用）
mysqldump -u lostfound -p --single-transaction campus_lostfound > backup_$(date +%F).sql
# 同步上传目录
rsync -a server/instance/uploads/ /data/backup/uploads/
```

- 应用日志：`server/logs/lostfound.log`（RotatingFileHandler，2MB × 5 份）
- 业务日志：MySQL `t_operation_log`，管理员后台可按对象追溯
