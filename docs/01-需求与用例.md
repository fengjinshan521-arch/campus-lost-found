# 校园失物招领信息平台 —— 需求分析与用例说明

## 1. 项目目标

面向校园网内网环境，构建一套覆盖 **拾获登记 → 信息发布 → 检索匹配 → 认领确认 → 结果归档** 完整业务闭环的失物招领信息平台，实现全流程状态可追溯、操作留痕、敏感信息脱敏。

## 2. 用户角色

| 角色 | 编码 | 职责 | 典型操作 |
|---|---|---|---|
| 学生用户 | student | 发布寻物启事、登记拾获、提交认领、接收通知 | 登记、检索、认领、查看通知 |
| 楼管/保卫处 | staff | 批量录入拾获物品、审核认领申请、归档 | 审核、归档、管理物品 |
| 系统管理员 | admin | 用户与角色管理、分类维护、统计看板、日志追溯、系统参数 | 全部后台功能 |

## 3. 功能模块清单（10 个）

1. 用户与权限管理（注册、登录、身份认证、角色区分、加盐哈希、会话与访问控制）
2. 拾获登记（自动分区归一化、关键词抽取、单号生成、图片上传）
3. 寻物启事发布（含酬金、加急标记）
4. 分类检索与模糊搜索（关键词 + 分类 + 分区 + 状态 + 时间范围 + 分页）
5. 匹配推荐（六因子加权算法，可解释、阈值过滤、幂等）
6. 认领确认与状态流转（状态机强制校验，全部变更留痕）
7. 消息通知（站内信，匹配/认领/结果/系统四类）
8. 后台管理（用户启停与角色调整、分类维护、公告广播）
9. 数据统计（认领率、分类分布、趋势、高发地点、处理时长、状态漏斗）
10. 操作日志追溯（按业务对象 ID 拉出完整时间线）

## 4. 用例清单

| 编号 | 用例 |  actor | 前置条件 | 主流程 | 异常流 |
|---|---|---|---|---|---|
| UC-01 | 用户注册 | 游客 | 无 | 填写用户名/密码/资料 → 唯一性校验 → 密码强度校验 → 加盐哈希入库 → 自动登录 | 用户名/邮箱/学号重复；密码强度不足 |
| UC-02 | 登录与登出 | 全部 | 已注册 | 提交账号密码 → 失败计数校验 → 校验哈希 → 建立会话 | 连续 5 次失败锁定 10 分钟；账号被禁用 |
| UC-03 | 校内身份认证 | 学生 | 已登录 | 填写学号与姓名 → 校验唯一性 → 置 verified | 学号被他人占用；格式不合法 |
| UC-04 | 拾获登记 | 全部 | 已登录 | 填写标题/分类/地点/时间 → 分区归一化 + 关键词抽取 → 生成 LF 单号 → 自动匹配并通知疑似失主 | 必填项缺失；时间格式错误 |
| UC-05 | 寻物启事发布 | 全部 | 已登录 | 同上，生成 XS 单号，可填酬金与加急 | 同上 |
| UC-06 | 分类检索与模糊搜索 | 全部 | 无 | 关键词 + 分类/分区/状态/时间筛选 → 分页返回 | 无结果返回空列表而非报错 |
| UC-07 | 匹配推荐 | 全部 | 存在未认领的寻物/拾获 | 计算六因子加权分 → 过滤低于阈值项 → 展示推荐理由 | 无候选则展示空态 |
| UC-08 | 提交认领 | 学生 | 物品处于未认领 | 填写理由（≥5 字）与联系方式 → 物品转待确认 → 通知登记人 | 认领自己登记的物品；重复提交；物品状态不符 |
| UC-09 | 认领审核 | 登记人/职工/管理员 | 认领单待确认 | 通过 → 物品转已认领，其余申请自动驳回；驳回 → 无其它申请时物品回退未认领并扣信用分 | 非法状态流转被状态机拦截 |
| UC-10 | 归档结案 | 登记人/职工/管理员 | 认领单已通过 | 认领单与物品同时转已归档（终态） | 归档后再流转抛异常 |
| UC-11 | 消息通知 | 全部 | 已登录 | 站内信列表、未读数、标记已读 | 越权操作他人通知被拒 |
| UC-12 | 后台统计与日志追溯 | 职工/管理员 | 对应角色 | 统计看板；按 target_type + target_id 拉全链路日志 | 非职工访问 403 |

## 5. 核心业务流程

```
拾获登记 ──▶ 信息发布 ──▶ 分类检索/模糊搜索 ──▶ 匹配推荐（六因子加权）
                                                      │
                                                      ▼
结果归档 ◀── 交付 ◀── 审核确认 ◀── 提交认领 ◀── 通知失主
     │
     └──▶ 操作日志（每一步均留痕，可按对象 ID 全程追溯）
```

## 6. 非功能性需求

- **安全性**：PBKDF2-HMAC-SHA256 加盐哈希（12 万次迭代）、CSRF 全站防护、角色越权拦截、上传文件魔数校验、敏感信息脱敏、登录防爆破。
- **可追溯性**：所有写操作落 `t_operation_log`，记录操作人、IP、UA、目标对象、变更前后值、结果。
- **性能**：关键查询建复合索引、分页查询（每页 12 条）、匹配结果持久化避免重复计算、静态资源由 Nginx 托管。
- **可移植性**：开发与生产差异仅体现在 `.env` 与 `app/config.py`，切换数据库只需修改连接串。
